# 银龄智伴全站 UI 统一设计文档

## 目标

在现有功能已基本打通的基础上，将首页、认证流、老人端、子女端、社区、聊天、设置等主要页面统一到一套清晰的设计系统中。统一不等于完全同质化，而是建立“同一产品、两层气质”的视觉结构：品牌页保留温暖识别，功能页统一收口到可信赖的服务体验。

## 设计方向

采用“双层统一”方案：

- **基础层统一**：颜色 token、圆角等级、卡片系统、标题层级、按钮规格、提示条样式、页面留白规则全部统一
- **页面气质分层**：
  - 品牌页（首页 / 登录 / 角色）保留暖橙品牌感
  - 功能页（老人端 / 子女端 / 社区 / 聊天 / 设置）统一为蓝白服务感

这样既能保留银龄智伴的品牌温度，也能让功能页看起来像同一套正式产品，而不是多个页面风格拼接在一起。

## 视觉系统

### 颜色体系

在 `app_theme.dart` 中明确拆分 token：

- `brandWarm*`：品牌暖橙系，主要给首页、登录、角色页使用
- `serviceBlue*`：服务蓝系，主要给老人端、子女端、社区、聊天、设置页使用
- `surface` / `surfaceAlt`：统一卡片底色和分层底色
- `borderSoft`：统一浅边框
- `success` / `warning` / `danger`：统一状态提示色

原则：
- 不再让每个页面各自定义临时颜色
- 不同页面的卡片、提示条、按钮都从统一 token 出发

### 圆角与阴影

统一圆角等级，例如：

- `16`：小型标签、提示条、小卡片
- `24`：标准卡片与列表项
- `32`：hero 卡、顶部大模块

阴影统一轻量化：
- 品牌页允许更柔和的暖色氛围阴影
- 功能页统一为更克制的服务卡片阴影

### 字体层级

统一标题与正文层级：

- 页面主标题：同一字重和字号区间
- 分区标题：统一 `titleLarge`
- 卡片标题：统一 `titleMedium`
- 正文与说明文：统一行高和颜色深浅

避免某些页标题过粗、某些页正文偏灰、某些页信息层级失衡。

## 页面分层策略

### 品牌页

包括：
- `landing_page.dart`
- `auth_page.dart`
- `role_select_page.dart`

处理原则：
- 保留暖橙品牌主轴
- 统一按钮、卡片、标题层级、背景渐变密度
- 让品牌页与功能页在组件节奏上连续，但情绪更温和

### 功能页

包括：
- `elderly_home_page.dart`
- `child_home_page.dart`
- `community_feed_page.dart`
- `chat_page.dart`
- `settings_page.dart`

处理原则：
- 统一成蓝白服务页系统
- 顶部 hero 卡、信息卡、状态条、列表项都遵守同一套卡片语言
- 聊天页、社区页、设置页不再看起来像独立视觉系统

## 重点统一对象

### 聊天页

当前聊天页仍保留相对独立的暖色头像头部和独立消息风格，是最需要收口的页面之一。

目标：
- 顶部头部、风险提示条、错误条、消息卡片、输入区都采用统一服务页样式
- 保持聊天可读性，但不与社区页、设置页脱节

### 社区页

当前社区页已经有 hero 卡和分区感，但仍偏暖色信息卡片风。

目标：
- 调整到服务页体系
- 保留互助氛围，但颜色和卡片系统与子女端/老人端一致

### 设置页

目标：
- 使用统一设置面板样式
- 与聊天、社区、老人端看起来属于同一功能系统

## 交互与状态统一

以下元素统一规则：

- `SnackBar`
- 风险提示条
- 错误条 / 错误卡
- 空态卡
- 加载态 / 线性进度条
- 二级操作按钮

原则：
- 状态反馈颜色和边距统一
- 错误不再有的页面偏红重、有的页面偏灰轻
- 加载态和刷新态保持同一语言

## 响应式策略

全站统一响应式断点思想：

- 手机：单列、紧凑、触控优先
- 平板：开始双列或分区
- 桌面：更大容器宽度和并排信息区

统一内容最大宽度、页面横向 padding、hero 卡和卡片组 spacing，避免有的页面很宽、有的页面很挤。

## 实施顺序

1. 收口 `app_theme.dart` 的全站 token 和基础组件规范
2. 统一功能页（聊天 / 社区 / 设置）到服务页系统
3. 微调首页 / 登录 / 角色页与功能页的衔接
4. 回归验证不同端宽下的布局稳定性

## 测试策略

- 优先保留现有功能测试
- 为关键页面补少量结构级视觉回归断言
- 重点关注：
  - 页面主标题仍存在
  - 关键入口仍可点击
  - 响应式分栏仍成立
  - 聊天和社区主要交互未被样式重构破坏

## 不在范围内

- 改业务流程
- 新增后端接口
- 重写整套导航结构
- 做深度动画系统改造
