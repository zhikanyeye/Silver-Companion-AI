# 银龄智伴 Landing/Auth/Role Flow 重设计

## Goal
- 将首页改为品牌优先的产品落地页，突出“银龄智伴”的品牌形象与核心价值。
- 首页右上角仅保留 `登录`、`注册` 两个主操作按钮，不在首页展示角色选择。
- 登录与注册统一到同一个认证界面，通过 Tab 切换模式。
- 认证提交成功后，再进入独立角色选择页，仅提供 `我是老人`、`我是子女` 两个入口。
- 优化 Landing/Auth/Role 三个页面的布局、视觉与动效，延续暖橙品牌风格。
- 不破坏现有 `AI / chat / community / elderly / child` 路由可达性。
- 认证仅用于演示，允许弱校验，不接真实后端。

## User Flow
1. 用户进入 `/`，看到品牌首页内容和右上角 `登录`、`注册` 按钮。
2. 点击任一按钮，进入统一认证页 `/auth`：
   - `登录` 默认打开登录 Tab
   - `注册` 默认打开注册 Tab
3. 用户填写表单并提交，前端做最小校验。
4. 提交成功后跳转到 `/select-role`。
5. 用户在角色选择页选择：
   - `我是老人` -> `/elderly`
   - `我是子女` -> `/child`
6. 登录后仍可继续访问 `AI`、`chat`、`community` 等现有页面。

## Route Strategy
- `/`：Landing Page
- `/auth`：统一认证页
- `/select-role`：角色选择页
- `/elderly`：老人页
- `/child`：子女页
- 保留现有业务路由：`/chat`、`/community` 等

## Visual Design
- 保持暖橙品牌系统，使用橙色、米白、浅金等暖色层级。
- Landing 页面强调品牌、价值和可信赖感，而不是功能分流。
- 顶部导航保持简洁，右上角突出 `登录`、`注册`。
- Auth 页面使用居中卡片式布局，视觉上与首页保持统一，但更聚焦完成认证。
- Role 页面保持极简，仅展示角色选择，不混入其他复杂内容。

## Motion Design
- Landing 首屏采用轻量淡入、上移或分层出现动画。
- 从首页进入认证页时，使用统一的淡入或滑入过渡。
- 登录 / 注册 Tab 切换使用短时长内容切换动画。
- 角色卡片增加 hover / tap / selected 状态反馈。
- 动效控制在可测试范围内，避免过长、循环或复杂时序。

## Testing Strategy
- Landing 页面测试：存在品牌 Hero、`登录`、`注册`，且不出现角色入口。
- Auth 页面测试：共用认证容器、默认 Tab 正确、弱校验与提交可触发。
- Role 页面测试：只显示两个角色选项，点击后跳转到 `/elderly` 或 `/child`。
- 回归测试：登录后仍可访问 `AI / chat / community / elderly / child`。

## Out of Scope
- 真实登录注册、短信验证码、邮箱验证、OAuth
- 服务端会话、数据库持久化、生产级安全策略
- 现有 `AI / chat / community / elderly / child` 的业务重构
